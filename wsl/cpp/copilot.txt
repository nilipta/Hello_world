- `/dev/sdd` → This is your **main WSL virtual disk (ext4.vhdx)**, about 1 TB in size. That’s where your Ubuntu root filesystem lives.  
- `tmpfs` mounts (like `/tmp`, `/run`, `/run/shm`) → These are **RAM-backed filesystems**. They don’t touch your SSD and vanish when WSL shuts down. Perfect for temporary builds.  
- The repeated `none` mounts are **WSL system overlays** (drivers, libraries, WSLg graphics support).

## 🛠 Using RAM for C++ Development in Ubuntu WSL

Since you already have Ubuntu 26 installed, you can **compile and run projects entirely in RAM** by using `tmpfs`:

1. **Create a RAM disk directory**
   ```bash
   mkdir ~/ramdisk
   sudo mount -t tmpfs -o size=2G tmpfs ~/ramdisk
   ```
   - This gives you a 2 GB RAM-backed filesystem at `~/ramdisk`.

2. **Move your project there**
   ```bash
   cp -r ~/my_cpp_project ~/ramdisk/
   cd ~/ramdisk/my_cpp_project
   ```

3. **Build inside RAM**
   ```bash
   cmake .
   make
   ./my_program
   ```
   - All compilation happens in memory → no SSD wear, faster builds.  
   - When WSL shuts down, everything in `~/ramdisk` disappears.  

4. **Keep source persistent, builds volatile**
   - Store your source code in `/home` (on `/dev/sdd`).  
   - Only copy builds into RAM (`~/ramdisk`) → reproducible, isolated, and safe.

## ⚖️ Why This Helps

| **RAM builds** | **Disk builds** |
|----------------|----------------|
| Faster compilation | Slower (SSD I/O bottleneck) |
| No SSD wear | Continuous SSD writes |
| Vanishes on shutdown → isolation | Persistent binaries |
| Great for testing | Better for long-term storage |
